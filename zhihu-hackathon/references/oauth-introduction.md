# 初始化时的 OAuth 介绍与选择

## 对用户展示的固定文案

面向缺乏技术知识储备的学生用户，直接展示下面这段。不要追加协议名、Token、回调参数或安全术语。

```text
已成功安装 zhihu-hackathon skill，在创建项目前，请确认是否需要让你的应用接入「知乎账号登录」能力。

接入后，你的应用可以：
- 让其他用户使用知乎账号登录你的应用；
- 显示用户的知乎昵称、头像等公开信息；
- 读取该登录账号的创作内容、关注用户、收藏夹等信息。

需要注意：电脑上的本地测试地址只能预览页面，无法完成知乎登录。你需要先把应用部署到 Cloudflare、Sealos 等在线部署平台，再用部署后的公网地址配置和测试登录。部署与配置过程我会继续协助你完成。

请先选择是否在应用中接入知乎账号登录功能。
```

等待用户明确回答后再创建项目：

- 用户明确选择接入：生成 OAuth 版。先支持本地页面预览；真实登录必须等部署完成并取得公网 HTTPS 回调地址后测试。
- 用户明确选择不接入：生成基础版，不收集 OAuth 凭证，不包含 OAuth 页面、路由、Token 或用户数据功能。

## Agent 内部执行规则

以下内容不要塞进首次介绍文案，但执行时必须遵守：

- 本地默认预览地址是 `http://127.0.0.1:4173/`，它不能作为本项目的真实 OAuth 回调地址。
- 部署到 Cloudflare、Sealos 等平台后，使用 `https://<public-domain>/auth/callback`，并确保和知乎开放平台登记值完全一致。
- 本地调试密钥存 macOS 钥匙串；部署后使用平台提供的 Secret/环境变量能力，不把密钥写进源码或构建产物。
- 实测回调可能不返回 `state`，且当前没有 PKCE、refresh token、撤销或解绑协议；只能标记为黑客松联调能力。
- 用户必须亲自完成知乎最终授权确认。
