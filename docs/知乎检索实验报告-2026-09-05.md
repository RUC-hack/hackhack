# 知乎检索 Loop 实验报告

> 日期：2026-09-05  
> 实验：`quota-paired-v1`  
> 目的：验证“构建 query → 调用知乎搜索 → 返回可解析回答”的 loop 是否能稳定工作。

## 结论

接口层面的 loop 已验证成功：8 次真实调用全部返回 HTTP 200、业务码 `0`，8 次响应均通过 schema 校验，共返回 80 条结果，没有空结果、限流或其他失败。

这证明当前 Access Secret、知乎搜索接口、请求参数、响应解析和 JSONL 记录链路均可用。它还不能单独证明 generated query 在总体人群上显著优于 baseline；本轮只有 4 个配对案例，内容质量仍需人工标注后再报告 precision@5。

## 环境与额度

- 本轮使用的本地环境文件：`.env.zhihu-5000.local`
- 该文件已被 `.gitignore` 忽略，不应上传仓库。
- 实验前知乎搜索额度：`5000 / 5000`
- 实验后知乎搜索额度：`4992 / 5000`
- 本轮实际消耗：8 次
- 知识库额度未用于本轮实验：`500 / 500`

## 实验设计

4 个案例分别运行两种条件：

- `baseline`：用户原话直接作为 query；
- `generated`：由 query builder 预先生成的一条短 query。

执行顺序已交错预注册，避免一种条件总在另一种条件之前调用。每次请求 `count=10`，调用间隔 15 秒；遇到 `30001` 会立即停止。

执行命令：

```powershell
node .\experiments\zhihu-retrieval-loop\run-quota-study.mjs `
  --env .env.zhihu-5000.local `
  --generated .\.runtime\experiments\single-queries-quota-v1.json `
  --live `
  --delay-ms 15000 `
  --timeout-ms 30000
```

## 结果

| 指标 | 总计 | baseline | generated |
|---|---:|---:|---:|
| 调用次数 | 8 | 4 | 4 |
| 业务成功 | 8 | 4 | 4 |
| schema 合法 | 8 | 4 | 4 |
| 返回结果数 | 80 | 40 | 40 |
| 平均每次结果数 | 10 | 10 | 10 |
| 平均延迟 | — | 608 ms | 870 ms |
| 限流/其他失败 | 0 | 0 | 0 |

延迟总体：p50 `661 ms`，p95 `1483 ms`，最大 `1483 ms`。

## 主题相关性观察

- C01（计算机考研/就业）：generated 前列直接出现“计算机专业是考研还是就业”等标题；baseline 也能召回同主题内容，但前列更宽泛。
- C03（北京互联网 vs 家乡银行）：两种条件都能召回“北京大厂/家乡国企”“大城市/家乡”等高度相关内容。
- C05（放弃保研、跨专业）：generated 前列直接命中“放弃保研、跨考、后悔/经历”；baseline 前几条包含转专业泛讨论，后段才出现保研跨考内容。
- C07（考研失败后二战或工作）：generated 前列出现“二战失败反思”“二战还是工作”“后来怎么样”等直接相关标题。

这是主题命中观察，不等同于人工 relevance、lived experience 或 evidence sufficiency 评分。
