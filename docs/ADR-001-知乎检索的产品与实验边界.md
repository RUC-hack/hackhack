# ADR-001：分离知乎产品接口与检索验证 loop

- 状态：已采用
- 日期：2026-09-04

## 背景

第一版 `experiments/zhihu-retrieval-loop/run-search.mjs` 同时承担了 HTTP 调用、响应校验、实验编排和结果存储。真实运行证明鉴权和接口可用，但连续调用出现业务码 `30001`。旧 runner 仍继续执行剩余任务，导致限流响应占据大部分结果。

实验需要保留原始响应、固定随机种子和对照组；产品需要稳定数据结构、缓存、脱敏日志、明确错误和降级能力。两者不能使用同一个顶层接口。

## 决策

采用三层边界：

```text
产品应用 / Agent Orchestrator
  -> RetrievalService
       -> ZhihuProvider
            -> ZhihuSearchClient

实验 runner
  -> ZhihuSearchClient.searchRaw()
```

1. `ZhihuSearchClient` 是唯一知道知乎 URL、Header、业务码和原始 schema 的模块。
2. `ZhihuProvider` 对产品提供稳定 `SourceDocument`，负责去重、缓存和日志。
3. `RetrievalService` 负责在限流、超时等可用性故障时切换本地 Provider。
4. 实验通过 `searchRaw()` 记录官方原始响应，但它的 JSONL 不构成产品契约。
5. `30001` 不自动重试。产品层转入缓存或本地数据；实验层立即暂停并支持续跑。
6. 产品联网由 `ALLOW_LIVE_EXTERNAL_CALLS` 控制；实验联网还需要 `--live` 或该环境开关。

## 结果

- 前端不接触 Access Secret，也不直接依赖知乎字段名。
- 官方字段变化只需修改 Client 和契约测试。
- 重复 query 优先命中缓存，降低配额消耗。
- 限流成为可观测、可降级的状态，不再表现为 200 HTTP 下的“空成功”。
- 实验可以继续比较 baseline、generated 和 oracle，同时分批执行并保留失败率。

## 非目标

- 本次不实现 Query Builder 或 Answer Builder。
- 本次不把搜索摘要当作完整回答。
- 本次不实现绕过知乎限流的 Secret 轮换。
- `LocalDatasetProvider` 的数据和实现仍需后续补充。
