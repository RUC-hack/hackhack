# 前端 A 移植到前端 B：详细实施计划

> 目标：保留前端 B 的真实后端能力，同时高效留存前端 A 已完成的视觉、交互和产品表达。本文不是“把 A 全部复制进 B”，而是按价值迁移、按风险验收。

## 执行状态（2026-09-05）

本计划已在当前工作区完成实施：

- B 已使用正式的 `src/journey.css`，运行时不再引用 A；
- A 的输入仪式、请求等待、路径列表、人物池、人物详情和本机收藏已经保留在 B；
- 等待动画只跟随真实请求生命周期，不再用定时器宣布检索成功；
- `AnswerEnvelope` 的 summary、sections、assumptions、unknowns、limitations、next_actions 均有可见出口；
- 来源读取失败会保留 `source_id` 并显示失败状态，不会静默删除或补造人物；
- `demo/curated-data.js` 已从 `qa.js` 拆出，curated、Mock、本地降级和真实知乎来源分别标识；
- A 已完整归档至 `src/prototypes/frontend-a/`，原多页流程和草稿功能仍可运行；
- 自动化测试为 54/54 通过；浏览器已验收 curated 全流程、live + Mock API 链路、后端不可达错误、390px 移动端、收藏/取消收藏和 A 归档入口；
- 当前 `.env.local` 的外部调用安全门为关闭状态，因此本次前端迁移没有额外消耗知乎或 DeepSeek 额度。

## 1. 现状与总原则

### 前端 A

位置：`src/staging_src/`

优势：

- 问题输入、匹配等待、路径展示、人物池和人物详情形成了完整体验；
- 视觉完成度较高，响应式和 reduced-motion 适配较完整；
- 有收藏、人物提问、人群提问等交互概念。

限制：

- `analyzeQuestion()` 只是关键词分类；
- 路径和人物来自 `journey-data.js` 固定演示数据；
- 匹配进度由定时器模拟；
- 不调用项目的 session、DeepSeek 和知乎接口。

### 前端 B

位置：`src/index.html`、`src/app.js`、`src/styles.css`、`src/qa.*`

优势：

- `qa.js` 已连接 session/message/source API；
- 能显示模型追问、结构化答案和知乎来源；
- 支持 `curated` 稳定演示与 `live` 真实链路；
- 已复用 A 的 `journey.css`、结果页结构和人物视觉。

当前问题：

- B 运行时直接引用 `staging_src/journey.css`；
- `qa.js` 同时负责 API、静态 demo、动画和结果渲染，职责过重；
- A/B 文件重名，容易修改错文件；
- 静态演示结果和真实结果共存在一个文件中，数据来源边界不明显。

### 迁移原则

```text
A 提供表现层成果：布局、视觉、动画、交互语言
B 保留业务层能力：API、session、真实状态、source_id、错误处理
后端保持业务真相：DeepSeek、知乎、证据、答案
```

不要求把 A 的所有文件并入 B。任何功能只要满足以下一种情况，就算被有效保留：

1. 已迁入 B 并由真实数据驱动；
2. 作为明确标注的 demo 功能保留；
3. 作为完整原型归档，供后续恢复或参考；
4. 有意暂缓，并记录缺少的后端能力。

## 4. 数据边界：迁移中最重要的约束

A 的页面组件只能消费 B 生成的 ViewModel，不直接理解后端原始响应。

### 后端返回的真实结构

```text
AnswerEnvelope
├─ summary
├─ sections[]
│  ├─ kind
│  ├─ title
│  ├─ content
│  └─ source_ids[]
├─ assumptions[]
├─ unknowns[]
├─ limitations[]
└─ next_actions[]

SourceDocument
├─ source_id
├─ title
├─ author
├─ raw_summary
├─ url
├─ content_type
└─ metadata
```

### B 应生成的前端 ViewModel

```text
MatchedPath
├─ id
├─ number
├─ title
├─ excerpt
├─ sourceIds[]
└─ sources[]

SourcePerson
├─ sourceId
├─ displayName
├─ title
├─ summary
├─ url
├─ sourceType
├─ voteCount（可选）
└─ provenance
```

映射原则：

- `section` 可以显示为一条“路径/主题”，但不能声称是概率分类；
- 一个知乎来源可以作为一位“人生样本”，但页面必须标明它是公开回答/文章/讨论；
- 后端没有年龄、时间线或人生结局时，前端不得从 A 的模板补造；
- 没有来源的 section 仍可展示为模型总结，但不能生成虚构人物；
- 所有外链继续使用后端返回的 URL 和 `source_id`。

## 5. 分阶段实施

## 阶段 0：冻结基线与建立验收表

目标：在搬运前留下 A/B 可比较的基线。

操作：

1. 不修改 `src/staging_src/`；先把它视为只读原型。
2. 分别记录以下页面的桌面和手机截图：
   - A：`question.html`、`matching.html`、`paths.html`；
   - B：`qa.html?mode=curated`、`qa.html?mode=live`。
3. 运行 `npm test`，记录现有通过数。
4. 手动记录 B 的功能：启动、输入、追问、回答、来源、重置、错误提示。
5. 创建独立分支，例如 `feat/frontend-a-into-b`。

完成标准：迁移前截图、测试结果和功能清单齐全。

## 阶段 1：解除 B 对 staging 目录的运行时依赖

目标：让 `staging_src` 成为真正的参考原型，而不是生产依赖。

涉及文件：

- 来源：`src/staging_src/journey.css`
- 新文件：`src/journey.css`
- 修改：`src/qa.html`

操作：

1. 将 B 实际使用的 `.journey-results-*`、`.journey-path-*`、`.journey-people-*`、动画和响应式规则提炼到 `src/journey.css`。
2. 将 `qa.html` 的引用从 `staging_src/journey.css` 改为 `journey.css`。
3. 不复制 A 的 question/crowd composer 等当前 B 不使用的样式。
4. 保留 `qa.css` 作为 B 的尺寸和状态覆盖层。
5. 检查 `styles.css → journey.css → qa.css` 的加载顺序。

完成标准：

- B 不再引用 `/staging_src/`；
- curated/live 两种页面外观不退化；
- 桌面、900px、600px 三档布局正常；
- reduced-motion 仍有效。

回退方式：只需恢复 `qa.html` 原引用；A 文件未被改动。

## 阶段 2：迁移问题输入和匹配体验

目标：保留 A 的输入仪式感和匹配动画，同时继续使用 B 的真实 session/API。

涉及文件：

- 参考：`staging_src/question.html`、`matching.html`、`journey.js`
- 修改：`src/qa.html`、`src/qa.css`、`src/qa.js`

操作：

1. 保留 B 的 `startSession()` 和输入校验，不复制 A 的页面跳转。
2. 使用 A 的标题比例、留白、步骤编号和 textarea 视觉优化 B 的输入区。
3. 保留 B 的 `startSearchRitual()`，吸收 A 的人群流动和阶段出现效果。
4. 动画开始条件绑定真实请求开始，结束条件绑定真实请求成功/失败。
5. 可以设置“最短展示时间”保证体验连续，但不得设置固定时间后假装成功。
6. 当前后端没有流式阶段事件，因此阶段文案应写成“正在理解/正在寻找/正在整理”，避免声称某个后端步骤已经完成。
7. 请求失败时立即停止动画并展示 B 的错误信息和重试入口。

完成标准：

- curated 和 live 都有一致的输入与等待体验；
- live 模式仍真实发送 `/api/sessions` 和 `/messages`；
- 网络失败不会进入假结果页；
- 连续点击不会产生重复 turn；
- 键盘操作和屏幕阅读器状态不退化。

## 阶段 3：完成真实答案到 A 结果视觉的适配

目标：让 A 的路径/人物表现完全由后端 `AnswerEnvelope + SourceDocument` 驱动。

涉及文件：

- 参考：`staging_src/paths.html`、`journey.js`
- 修改：`src/qa.html`、`src/qa.js`、`src/journey.css`、`src/qa.css`

操作：

1. 保留 B 的 `buildMatchedPaths()`，明确它是唯一 answer → path 适配入口。
2. 对每个 section 生成稳定的本地 path ID，不把标题当数据库 ID。
3. 保留 section 的原始 `source_ids`，不得按视觉需要随意补来源。
4. `renderMatchedPaths()` 先批量调用 `getSource()`，然后再渲染人物池。
5. 来源加载失败时显示“来源暂时无法读取”，不要删除整条路径。
6. `renderSourceDetail()` 只显示 SourceDocument 中存在的信息。
7. 把 assumptions、unknowns、limitations 和 next_actions 放在结果末尾或独立折叠区，不能因路径视觉而丢失。
8. 继续保留知乎原文链接、来源类型和降级来源说明。

完成标准：

- AnswerEnvelope 的全部信息都有可见出口；
- 每个显示的知乎人物/卡片都对应真实 `source_id`；
- 不出现 A 固定人物混入 live 结果；
- 本地降级来源有明显标识；
- 0 来源、1 来源、多来源均能正常显示。

## 阶段 4：隔离 curated 演示数据

目标：保留 B 当前稳定演示能力，但让维护者不会误把 demo 当生产数据。

涉及文件：

- 来源：`src/qa.js` 中的 `DEMO_SOURCES`、`DEMO_ANSWER`
- 新文件：`src/demo/curated-data.js`
- 修改：`src/qa.html`、`src/qa.js`

操作：

1. 将固定来源和答案移出 `qa.js`。
2. demo 对象继续使用与真实 AnswerEnvelope/SourceDocument 相同的最小字段。
3. 所有 demo `source_id` 保持 `demo:` 前缀。
4. 页面在 curated 模式显示“精选演示内容”标识。
5. 保留以下调试方式：
   - `?mode=curated`：强制本地演示；
   - `?mode=live`：强制真实后端；
   - 无参数：按当前规则自动分流。
6. 将自动分流规则集中在一个函数中，避免散落关键词。

完成标准：`qa.js` 中不再包含大段固定人物/答案，live 与 curated 的来源标识清楚。

## 阶段 5：选择性保留次级交互

这些功能不阻塞主链路，应逐项决定，不应一次性迁入。

### 收藏人物

建议迁入，优先级中等。

- 使用 `source_id` 作为收藏键；
- 只保存必要的显示快照和 URL；
- 来源失效时仍可删除收藏；
- 明确收藏只在当前浏览器保存。

### 向人物提问

暂不迁入正式 live。

可保留两种安全形式之一：

1. 生成“我还想追问什么”的文本，并作为下一轮 session 消息发送；
2. 仅保存为用户自己的问题草稿。

不能显示成已经向知乎答主发送消息。

### ASK THE CROWD

暂不迁入正式发布能力。

可以保留为“生成知乎提问草稿 + 复制”，明确说明不会自动发布。真正发布需要独立的写入 API、OAuth、用户确认和防滥用设计。

## 阶段 6：归档 A，而不是删除 A

目标：留存队友成果，并消除“哪个目录是正式前端”的歧义。

操作：

1. 在所有迁移项通过验收后，将完整 A 移到 `src/prototypes/frontend-a/` 或仓库级 `prototypes/frontend-a/`。
2. 保留 A 的 README、页面、脚本和静态数据，使其仍能独立启动。
3. 在 A 的 README 顶部注明：
   - 这是视觉/交互原型；
   - 不连接生产后端；
   - 正式入口是 `/qa.html`。
4. 不在同一提交中删除 A 和实现新功能；归档应是独立机械提交。

完成标准：仓库中只有一套正式入口，但 A 的成果仍可访问和比较。

## 6. 每阶段验证方法

### 自动测试

每一阶段都运行：

```powershell
npm test
```

重点保证：

- 前端静态服务器仍能读取 `/`、`/qa.html` 和资源；
- 后端 session/message/source API 不受影响；
- source_id 和答案契约测试继续通过；
- degraded flow 继续工作。

### 手动矩阵

| 模式 | 输入 | 验收重点 |
|---|---|---|
| curated | 毕业/读博/工作问题 | 无后端也能稳定演示，标明 demo |
| live + local | 普通人生选择 | session、多轮、路径、来源、限制 |
| live + zhihu | 固定 smoke 案例 | 真实来源、非降级、引用可打开 |
| live 错误 | 停止后端或模拟 30001 | 动画停止、错误清楚、不出现假结果 |
| mobile | 390px 宽度 | 输入、路径、人物详情可操作 |
| reduced motion | 系统减少动态效果 | 无持续漂移动画，信息仍完整 |

真实知乎/DeepSeek 测试只在阶段完成后运行一次，避免每次改 CSS 都消耗额度。

## 7. 建议提交顺序

每个提交只处理一个风险点：

```text
1. chore: freeze frontend A migration baseline
2. refactor: detach qa page from staging styles
3. feat: adopt frontend A question and matching experience
4. feat: map grounded answers into path and people views
5. refactor: isolate curated demo data
6. feat: preserve optional frontend A interactions（按需）
7. docs: archive frontend A as a runnable prototype
```

每个提交前执行：

```powershell
npm test
git diff --check
node scripts/scan-staged-secrets.mjs
```

不要使用一个“大迁移提交”同时改 HTML、CSS、API 和后端契约，否则出现问题时无法判断是视觉、数据适配还是接口造成的。

## 8. 明确不在本次迁移中做的事情

- 不重写后端 DeepSeek/知乎链路；
- 不把 A 的关键词匹配接到 live 模式；
- 不引入新的前端框架或打包器；
- 不为了复刻 A 而修改 AnswerEnvelope/SourceDocument 契约；
- 不实现真正的知乎发布和私信；
- 不删除 A 的完整原型；
- 不把缺失字段补成虚构人物信息。

## 9. 最小可交付范围

如果开发时间很紧，只完成以下四项也能达到主要目标：

1. 把 B 使用的 A 样式迁到正式 `src/journey.css`，解除 staging 依赖；
2. 保留并完善 B 当前的匹配动画；
3. 用真实 AnswerEnvelope/SourceDocument 驱动路径和人物视图；
4. 把 A 完整归档并写清正式入口。

这样可以保留 A 最有价值的成果，同时不动已经验证通过的后端主链路。

## 10. 最终验收定义

迁移完成不以“复制了多少文件”为标准，而以以下结果为标准：

```text
B 是唯一正式问答入口
A 仍作为完整原型留存
B 不再运行时依赖 staging_src
curated 与 live 来源清晰
真实答案完整映射为路径/人物视图
所有知乎卡片都有真实 source_id 和 URL
API、多轮、错误处理、降级、重置功能均保留
桌面、手机、键盘和 reduced-motion 可用
自动测试全部通过
```
