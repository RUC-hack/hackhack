# 浏览器端完整交互验收设计

服务端 HTTP 全链路已经由 `run-v3.mjs` 覆盖；当前 `src/index.html` 与 `src/app.js` 仍是概念展示页，没有调用 `/api/sessions`，因此浏览器端验收当前应标记为 `BLOCKED_BY_FRONTEND_WIRING`，不能把 HTTP 测试冒充成 UI 测试。

## 主场景 UI-E2E-01

输入与 `scenario.json` 相同。

1. 打开首页，输入模糊问题“我在两条路之间犹豫，不知道该怎么选。”并提交。
2. 提交后立即出现加载态；按钮防重复点击；网络层创建一个 session 并发送 `e2e-ui-turn-1`。
3. 页面显示模型追问，而不是提前给确定性建议。
4. 用户补充北京互联网 offer 与家乡银行的信息并提交 `e2e-ui-turn-2`。
5. 页面依次展示正在理解、正在检索、正在整理；同一条用户消息不重复出现。
6. 完整输出至少显示摘要、多个参照段、假设/未知、限制、下一步和来源卡片。
7. 每个有事实材料的段落都能映射到返回的 `source_id`；点击来源卡片能读取 `/api/sources/{id}` 并打开对应知乎 URL。
8. 刷新或网络重试不得重复创建同一 turn；相同 `client_turn_id` 返回相同结果。

通过条件：两轮请求均 HTTP 200，动作顺序为 `ask → respond`，最终状态为 `WAITING_FOR_FOLLOW_UP`，provider 为 `zhihu`、`degraded=false`，查询不超过 2 条，至少 1 个来源，控制台无异常，前端包和网络日志中不出现任何 Secret。

## 必测异常

| 场景 | 注入 | 预期界面 |
|---|---|---|
| 模型输出非法 JSON | mock 首次返回截断 JSON | 后端有界修复；前端继续加载或显示可重试错误，不显示原始模型垃圾 |
| 知乎额度耗尽 | mock `Code=30001` | 显示来源暂不可用/降级说明，不伪装成真实知乎结果 |
| 知乎空结果 | 返回 `Items=[]` | 显示材料不足，并邀请补充问题或改写 query |
| 网络超时 | 延迟超过客户端超时 | 保留用户输入，允许重试并复用原 `client_turn_id` |
| 连点提交 | 两次点击同一按钮 | 只产生一次逻辑 turn |
| 来源失效 | 来源 GET 返回 404 | 单卡片提示不可用，主体答案仍可阅读 |

## 自动化落地条件

前端接入 API 后再引入 Playwright 测试：用本地 mock provider 跑稳定 CI，用 `--live` 标签单独跑真实 DeepSeek + 知乎冒烟。CI 默认不得读取真实 Secret，也不得访问外部接口。
