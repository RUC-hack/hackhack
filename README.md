# 人生参照 / Life Experience Retrieval

“造物有心”黑客松开放创新组项目。

## 项目简介

我们希望帮助处在重大人生选择中的大学生，看到与自己处境相似的人曾经走过哪些路。

用户提出一个困惑，例如“考研还是工作”，系统不会直接替用户预测结果，也不会只返回一段泛泛的鸡汤，而是：

1. 通过多轮追问，明确用户真正面临的冲突、约束和偏好；
2. 使用知乎中的高相关、高质量回答作为人生经验样本；
3. 把自然语言案例整理为选择路径、动机、收益、代价、结果和遗憾；
4. 将多个案例聚合成几条可比较的人生路径；
5. 展示代表案例、来源链接和需要用户自己回答的问题。

核心价值不是“替你做决定”，而是让选择不再发生在真空中。

> 这些人生无法证明你会成功，只能证明你想象中的那条路，确实曾经有人走过。

## 产品定位

本项目是 **RAG for Decisions**，不是普通的“知乎搜索 + LLM 总结”：

```text
用户困境
  -> 冲突识别与追问
  -> 用户画像与约束
  -> 知乎经验检索
  -> 经验结构化抽取
  -> 人生路径聚类
  -> 收益 / 代价 / 代表案例
  -> 用户反思与决策辅助
```

知乎在系统中是一个 `Experience Source`，不是权威事实库。知乎样本存在选择偏差，高赞回答也不代表总体分布，因此系统不输出“你成功概率为 63%”之类的伪统计结论。

## 黑客松 MVP

第一版只聚焦“一次重大选择的人生参照”：

- 一个用户困境；
- 2～3 轮必要追问；
- 2～4 条知乎检索查询；
- 10～20 条候选经验；
- 3 条左右人生路径；
- 每条路径的收益、代价、适合人群和代表案例；
- 每个案例保留知乎标题、作者、摘要和原文链接；
- 知乎接口失败时切换到本地案例库。

不在 MVP 中实现：全方位人生管理、MBTI/人格诊断、精确成功率预测、复杂 Multi-Agent 编排和大规模用户系统。

## 知乎接口

项目随附了知乎官方 Skill 的文档和安装快照，主要能力包括：

- 知乎站内搜索；
- 全网搜索；
- 知乎热榜；
- 知乎直答；
- 当前账号的创作、关注和收藏查询。

本项目主要使用知乎站内搜索。调用官方接口需要在后端配置知乎开放平台 `Access Secret`，不要将凭证放入前端、源码、Git、日志或回答内容中。

知乎搜索结果中的 `ContentText` 是摘要，不保证是完整原文。系统应保留原始标题、作者、摘要和 URL，并使用本地案例库作为线上接口失败或结果不足时的降级方案。

## 开发建议

考虑到比赛时间有限，推荐先使用一个后端服务和一个 Agent 编排器，不要一开始拆成多个 Agent：

- API 层负责会话、消息、结果和健康检查；
- Agent 层负责追问、检索计划、经验抽取和路径总结；
- Provider 层统一知乎、本地数据和 Mock 数据；
- 日志层记录可复现的输入、来源和阶段状态；
- 前端只消费结构化结果，不直接访问知乎或大模型接口。

建议优先保证以下演示链路：

```text
输入“考研还是工作”
  -> 追问经济压力 / 研究兴趣 / 时间范围
  -> 检索多种路径案例
  -> 展示“直接工作 / 读研后就业 / 读研后转行”
  -> 对比每条路径的收益与代价
  -> 点击查看知乎来源
```

## 运行状态

当前仓库主要完成了项目材料、知乎 Skill 及黑客松初始化模板。真正的产品后端、前端和本地案例库仍需在此基础上实现。

## 重要边界

- 系统提供参照和反思，不替用户做人生决定；
- 不把知乎样本当作总体统计结论；
- 所有知乎来源尽量提供可检查的原文链接；
- 所有知乎调用和 Agent 对话按项目约束写入 `logs/`，并对密钥、Token 和隐私字段脱敏；
- 如果使用 OAuth，只用于“用户用知乎登录应用”的独立需求，不是本项目检索知乎经验的必要条件。
