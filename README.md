# 人生参照 / Life Experience Retrieval

“造物有心”黑客松开放创新组项目。

## 项目简介

我们希望帮助处在重大人生选择中的大学生，看到与自己处境相似的人曾经走过哪些路。

用户提出一个困惑，例如“考研还是工作”，系统不会直接替用户预测结果，也不会只返回一段泛泛的鸡汤，而是：

1. 通过多轮追问，明确用户真正面临的冲突、约束和偏好；
2. 使用知乎中的高相关、高质量回答作为人生经验样本；
3. 完整保留原始摘要和来源，再根据当前问题动态提取有依据的主题、经历片段和矛盾；
4. 从样本中发现可能的人生路径、共同主题或差异，不强迫所有经历进入预设分类；
5. 根据用户问题选择合适的表达方式，并展示代表案例、来源链接和仍待思考的问题。

核心价值不是“替你做决定”，而是让选择不再发生在真空中。

> 这些人生无法证明你会成功，只能证明你想象中的那条路，确实曾经有人走过。

## 产品定位

本项目是 **RAG for Decisions**，不是普通的“知乎搜索 + LLM 总结”：

```text
用户困境
  -> 冲突识别与追问
  -> 用户画像与约束
  -> 知乎经验检索
  -> 原始证据保留
  -> 开放式主题与经历解析
  -> 动态组织路径 / 张力 / 时间线 / 个案
  -> 带来源的人生参照
```

知乎在系统中是一个 `Experience Source`，不是权威事实库。知乎样本存在选择偏差，高赞回答也不代表总体分布，因此系统不输出“你成功概率为 63%”之类的伪统计结论。

## 黑客松 MVP

第一版只聚焦“一次重大选择的人生参照”。下面是资源预算而不是固定回答范式，系统可以根据问题复杂度提前结束、继续追问或调整检索规模：

- 一个用户困境；
- 少量必要追问，不要求固定轮数；
- 若干条面向不同角度的知乎查询；
- 足以覆盖主要差异的候选经验；
- 根据材料自然形成路径、主题、张力、时间线或独立个案；
- 回答可以是比较、叙事、案例拼图或反思问题，不要求固定栏目；
- 每个案例保留知乎标题、作者、摘要和原文链接；
- 知乎接口失败时切换到本地案例库。

不在 MVP 中实现：全方位人生管理、MBTI/人格诊断、精确成功率预测、复杂 Multi-Agent 编排和大规模用户系统。

## 信息表示原则

系统只固定软件协作所需的最小字段，例如来源 ID、原始摘要、URL、检索时间和证据引用；经历本身不使用封闭枚举。模型提取出的主题、背景、转折、感受、代价或其他观察以开放列表表达，并始终绑定原文证据。

无法归类、彼此矛盾或信息不完整的案例仍然保留。系统宁可明确标记“不确定”和“未观察到”，也不为了填满模板补造事实。

## 知乎接口

项目随附了知乎官方 Skill 的文档和安装快照，主要能力包括：

- 知乎站内搜索；
- 全网搜索；
- 知乎热榜；
- 知乎直答；
- 当前账号的创作、关注和收藏查询。

本项目主要使用知乎站内搜索。调用官方接口需要在后端配置知乎开放平台 `Access Secret`，不要将凭证放入前端、源码、Git、日志或回答内容中。

知乎搜索结果中的 `ContentText` 是摘要，不保证是完整原文。系统应保留原始标题、作者、摘要和 URL，并使用本地案例库作为线上接口失败或结果不足时的降级方案。

## 开发建议

考虑到比赛时间有限，推荐先使用一个后端服务和一个 Agent 编排器，不要一开始拆成多个 Agent：

- API 层负责会话、消息、结果和健康检查；
- Agent 层负责追问、检索计划、开放式经验解析和动态答案组织；
- Provider 层统一知乎、本地数据和 Mock 数据；
- 日志层记录可复现的输入、来源和阶段状态；
- 前端只消费结构化结果，不直接访问知乎或大模型接口。

建议优先保证以下演示链路；其中输出形式只是示例，由实际材料决定：

```text
输入“考研还是工作”
  -> 追问经济压力 / 研究兴趣 / 时间范围
  -> 检索多个角度的案例
  -> 保留无法归类或相互冲突的经历
  -> 按材料生成路径对比、关键张力或案例叙事
  -> 点击查看知乎来源
```

## 测试原则

测试不比较模型是否输出某一句固定文案，而检查可验证的不变量：来源是否可追溯、原始材料是否保留、无法归类的案例是否被丢弃、敏感信息是否进入日志、知乎故障时是否成功降级。完整测试分层见项目结构文档。

## 运行状态

当前仓库主要完成了项目材料、知乎 Skill 及黑客松初始化模板。真正的产品后端、前端和本地案例库仍需在此基础上实现。

## 重要边界

- 系统提供参照和反思，不替用户做人生决定；
- 不把知乎样本当作总体统计结论；
- 所有知乎来源尽量提供可检查的原文链接；
- 所有知乎调用和 Agent 对话按项目约束写入 `logs/`，并对密钥、Token 和隐私字段脱敏；
- 如果使用 OAuth，只用于“用户用知乎登录应用”的独立需求，不是本项目检索知乎经验的必要条件。
